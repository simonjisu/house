# 청약홈 분양·특별공급 API 연결

LH 분양 목록은 키 없이 수집합니다. 민간분양·특별공급의 청약홈 API는 다음 설정이 필요합니다. 키가 없으면 다른 수집은 계속하며 청약홈만 **미연결**로 표시합니다.

1. [공공데이터포털의 한국부동산원 청약홈 분양정보 조회 서비스](https://www.data.go.kr/data/15098547/openapi.do)에 로그인합니다.
2. **활용신청**을 눌러 개발계정 신청을 완료합니다. 포털 안내상 무료이며 개발단계는 자동승인입니다. 운영계정에는 별도 심의가 있습니다.
3. 마이페이지의 활용 신청 현황에서 해당 서비스의 승인 상태와 인증키를 확인합니다. **일반 인증키(Decoding)**를 복사합니다. Decoding 키를 권장합니다. 수집기는 Encoding 키가 입력된 경우에도 한 번만 디코딩하며, 복사 과정의 공백·줄바꿈을 정리합니다.
4. [house 저장소의 Actions Secrets 설정](https://github.com/simonjisu/house/settings/secrets/actions)에서 **New repository secret**을 누릅니다.
5. 이름은 정확히 `DATA_GO_KR_SERVICE_KEY`, 값에는 복사한 Decoding 키를 입력한 뒤 저장합니다. 기존 Supabase 설정은 그대로 둡니다. 추가 Variable은 필요 없습니다.
6. [Daily official notices](https://github.com/simonjisu/house/actions/workflows/collect.yml)에서 **Run workflow → main → Run workflow**를 누릅니다.
7. 작업이 성공하면 사이트를 새로 고침하고 로그인합니다. **수집 상태**를 펼쳐 청약홈이 ‘수집 정상’인지 확인합니다. ‘미연결’은 Secret 이름/누락, ‘수집 지연’은 승인 상태·키·API 상태를 확인해야 합니다. 키를 채팅·코드·공개 로그에 붙여넣지 않습니다.

서버 수집기만 키를 사용하며, 입력 키의 공백·줄바꿈을 정리하고, 퍼센트 인코딩된 키는 한 번만 디코딩한 뒤 쿼리 인코딩을 한 번 수행합니다. 키나 인증 헤더는 웹 빌드·자료·로그에 넣지 않습니다. 인증키가 없는 현재 단계에서는 실제 API 호출 성공을 검증하지 않았습니다. 키 등록 후 첫 수집 결과로 확인해야 합니다.

수집은 APT·민간사전청약·신혼희망타운의 최근 60일 서울/경기 공고로 제한합니다. 무순위/잔여세대, 오피스텔 등 별도 API는 아직 포함하지 않습니다. 목록 5페이지(페이지당 100건), 공고별 주택형 2페이지로 상한을 둡니다. 상한 내 완전성은 수집 상태에 표시합니다. LH와 청약홈 사이 공고가 중복될 수 있으며 출처별 원문을 유지합니다.

주택 분양/분양전환 임대는 `RENT_SECD`로 분리합니다. 신혼부부·신생아 특별공급 배정 수는 자격 판정이 아닙니다. 신생아 배정 수는 공공주택법 적용 공고에만 특별공급 구분으로 사용하고 민영 신생아 우선공급은 원문 확인이 필요합니다. null과 0을 구분해서 보존합니다. 소득·자산 조건은 여전히 미확인입니다.

전체 접수, 특별공급, 일반 1·2순위 해당지역/기타 경기/기타지역 날짜를 각각 보존합니다. **공급 방식**에서 특별공급을 선택하면 특별공급 종료일로 정렬합니다. 확인된 청약홈 특별공급 자료만 필터에 포함하며, LH 목록 마감일을 특별공급 기간으로 추정하지 않습니다. 접수시각은 원문 확인이 필요합니다.

공식 스키마: [공공데이터포털 Swagger](https://infuser.odcloud.kr/api/stages/37000/api-docs?1643022751478). 사용하는 API는 `getAPTLttotPblancDetail`, `getAPTLttotPblancMdl`입니다.
